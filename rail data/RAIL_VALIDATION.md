# Rail Corrugation Subsystem — Validation Write-up

**Task.** Classify each 1-second, 8-car axle-box recording as **Normal**,
**Side I**, or **Side II** corrugation (3-class).
**Scoring metric (PS3):** macro F1 across the three classes.

Every number here is regenerated by `python rail_validate.py`, which writes
`rail_validation_results.json`.

## 1. Data and split rationale

- 272 training files: **234 Normal / 24 Side II / 14 Side I** — heavily
  imbalanced, and Side I is critically small (14 examples).
- No official split is given (PS3 §2.3), so we validate with **repeated
  stratified 5-fold CV**:
  - *Stratified* keeps all three classes — including the 14 Side I files —
    present in every fold; a plain k-fold could put an entire class in one fold.
  - *Repeated* (5 seeds) exposes how much the score moves given so few Side I
    examples, rather than reporting one lucky split.
- **No leakage:** features are per-file physical/spectral summaries only (order
  spectrum, envelope, time-domain, side-contrast); no label, filename, or
  cross-file information enters the feature vector, and each fold fits a fresh
  `HistGradientBoostingClassifier` on its training folds only.

## 2. Feature-table integrity (why this validation is trustworthy without the raw Train/ folder)

`rail_validate.py` reads `rail_features_v2.csv` (272 rows: 101 features +
`filename` + `label`). This table was checked against the raw signals: recomputing
`features()` from the three provided raw sample files
(`SAMPLE_Train1_Normal`, `SAMPLE_Train2_SideII`, `SAMPLE_Train62_SideI`)
reproduces the saved rows to a **max absolute difference of ~1e-15**, and the
row order matches `Train_Labels.csv` (row 0 = Train1 = Normal, row 1 = Train2 =
Side II, row 61 = Train62 = Side I). So the saved table is a faithful,
correctly-labelled stand-in for recomputing all 272 files.

## 3. Results

Numbers are for the **shipped configuration** (`RailPipeline` default =
BorderlineSMOTE on training + HGB), reproduced by `python rail_validate.py`. The
baseline (no resampling, class_weight balanced) is shown alongside; Section 5
covers how the shipped method was chosen.

**Repeated stratified 5-fold CV (8 seeds):**

| Metric | Shipped (BorderlineSMOTE) | Baseline (no resampling) |
|---|---|---|
| Macro F1 | **0.815** (std 0.035, range 0.759–0.866) | 0.804 (std 0.034) |
| Normal F1 | 0.973 (std 0.004) | 0.972 |
| Side II F1 | 0.892 (std 0.021) | 0.893 |
| **Side I F1** | **0.579** (std 0.086) | 0.553 |
| **Side I recall** | **0.625** | 0.554 |

The per-seed std (±0.035) understates the swing on any *single* fold: a fold
holds only ~3 Side I files, so one Side I miss moves that fold's macro F1 by
~0.1. Always quote Rail **with its spread** — the 14-example Side I class makes a
bare point estimate misleading.

### Confusion matrix (out-of-fold, seed 0; shipped config; each file predicted once)

| true ↓ / pred → | Normal | Side I | Side II |
|---|---|---|---|
| **Normal** | 227 | 6 | 1 |
| **Side I** | 2 | 12 | 0 |
| **Side II** | 1 | 2 | 21 |

| Class | Precision | Recall | F1 | Support |
|---|---|---|---|---|
| Normal | 0.987 | 0.970 | 0.978 | 234 |
| Side I | 0.600 | 0.857 | 0.706 | 14 |
| Side II | 0.955 | 0.875 | 0.913 | 24 |
| **Macro avg** | 0.847 | 0.901 | **0.866** | 272 |

(Seed 0 is a favourable fold — 12/14 Side I recovered; the 8-seed *mean* macro
F1 of 0.815 is the number to report, not this single-seed 0.866.)

## 4. Honest read

- **Side I is still the bottleneck**, just less so. BorderlineSMOTE lifts its
  recall from 0.554 to 0.625 (≈ 1 more of the 14 files caught) and macro F1 from
  0.804 to 0.815; Normal and Side II are unchanged and strong (F1 0.98 / 0.91).
- The residual confusion is Side I ↔ Normal — expected, since a mild single-side
  corrugation is the hardest to separate from normal speed/ballast vibration.
- The +0.011 macro-F1 gain is within one std: a consistent, correct-direction
  improvement, not a fix. With 14 Side I examples the class remains the
  structural cap; the real lever is more Side I data (Section 5).

## 5. Lifting Side I — what we tested (`rail_sideI_experiments.py`)

Six methods, all evaluated under the same repeated stratified 5-fold CV, with any
resampling applied **inside each fold's training split only** (never on the
held-out fold), so the comparison is leakage-free. Confirmed at 8 seeds for the
top methods:

| Method | Macro F1 | Side I F1 | Side I recall |
|---|---|---|---|
| baseline (class_weight balanced) | 0.804 ± 0.034 | 0.553 | 0.554 |
| **BorderlineSMOTE (in-fold)** | **0.815 ± 0.035** | **0.579** | **0.625** |
| SMOTE (in-fold) | 0.814 ± 0.036 | 0.578 | 0.607 |
| extra Side I sample weight | 0.802 | 0.531 | 0.571 |
| SMOTE + ENN cleaning | 0.764 | 0.515 | 0.667 |
| two-stage (Normal-vs-fault → side) | 0.563 | 0.338 | 0.524 |

**Adopted: BorderlineSMOTE inside training** (now the default in
`RailPipeline(resample="borderline")`). It gave the best macro F1 and the best
Side I recall — it catches ~1 more of the 14 Side I files — and never hurt macro
F1 across runs. Up-weighting, ENN cleaning, and the two-stage split all made
things worse (ENN over-cleans the tiny classes; the two-stage's second model has
too few faults to separate Side I from Side II).

**Honest caveat.** The lift (+0.011 macro F1) is within one standard deviation.
It is a consistent, correct-direction improvement, not a fix: with only 14 Side I
examples the class is the structural cap on macro F1. The real levers still
require more Side I data:

- Raw-signal augmentation on the Side I windows (time-shift / speed-scale /
  noise) — not doable here because the full raw `Train/` folder isn't available
  in this environment; only 3 sample raw files are.
- Grouped CV if per-run/session metadata for the 272 files ever becomes
  available (none is provided now), to rule out same-run correlation.

## 6. Reproduce

```
python rail_validate.py             # Section 3  -> rail_validation_results.json
python rail_sideI_experiments.py    # Section 5 (6 methods) -> rail_sideI_results.json
```
The submission model uses the adopted method by default:
`RailPipeline().fit(TRAIN_DIR, "Train_Labels.csv")`
(pass `resample=None` to reproduce the prior baseline).
