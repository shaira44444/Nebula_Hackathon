# Door Subsystem — Validation Write-up

**Task.** Segment a continuous 50 Hz door-controller stream into open/close
cycles and classify each cycle Normal vs. Abnormal-resistance.
**Scoring metric (PS3):** IoU-weighted F1 — timing overlap × label correctness.

This document records exactly how the reported metrics were obtained. Every
number is regenerated by `python door_validate.py`, which writes
`door_validation_results.json`.

## 1. Data and split rationale

- 110 labelled segments in `Train_Segments_Answer.csv`: **80 Normal / 30
  Abnormal resistance** (a 73/27 imbalance).
- No official train/validation split is given, so per PS3 §2.3 we design and
  justify our own. Because the data is a time-ordered stream, we validate with
  **two** splits and require them to agree:
  - **Repeated stratified 5-fold CV (15 seeds)** — preserves the 80/30 class
    ratio in every fold; gives a reproducible headline number and its spread.
  - **Blocked chronological 5-fold CV** — segments sorted by start time and cut
    into contiguous blocks; each block is scored by a model trained only on the
    other blocks. This is the split that **cannot leak time** and mirrors
    deployment (train on past cycles, predict future ones).

## 2. Segmentation validation

`segment()` splits the stream on time gaps > 1 s. Matching its output to the
110 ground-truth rows by time overlap:

| Metric | Value |
|---|---|
| Ground-truth segments | 110 |
| Segments recovered (1:1) | **110 / 110** |
| Predicted segments | 110 |
| Mean IoU | **1.000** |
| Min IoU | **1.000** |

The silence between cycles is unambiguous, so boundaries are exact. Since IoU ≈
1 on the training set, the IoU weight in the PS3 metric is ~1 and the
IoU-weighted F1 reduces to plain classification F1 for these segments — so the
classification numbers below are the ones that drive the score.

## 3. Classification validation

| Split | Macro F1 | Normal F1 | Abnormal F1 |
|---|---|---|---|
| Repeated stratified 5-fold (15 seeds) | **0.988** (std 0.000) | 0.994 | 0.983 |
| Blocked chronological 5-fold | **0.988** | 0.994 | 0.983 |

The two independent splits give the same result, so the score is not an
artefact of a favourable random partition. std 0.000 across 15 seeds reflects
that the model is stable enough to land on the same single error every time —
not a placeholder.

### Confusion matrix (out-of-fold, all 110 segments, chronological CV)

| true ↓ / pred → | Normal | Abnormal resistance |
|---|---|---|
| **Normal** | 80 | 0 |
| **Abnormal resistance** | 1 | 29 |

| Class | Precision | Recall | F1 | Support |
|---|---|---|---|---|
| Normal | 0.988 | 1.000 | 0.994 | 80 |
| Abnormal resistance | 1.000 | 0.967 | 0.983 | 30 |
| **Macro avg** | 0.994 | 0.983 | **0.988** | 110 |

The single error is a **false negative** — one Abnormal-resistance cycle
classified Normal. The model produces **no false alarms** on Normal cycles
(Normal recall 1.000), which is the safer failure mode for a maintenance flag
that triggers inspection.

## 4. Why this is leakage-free

- **No target/flag leakage in features.** The feature vector is per-segment
  physical statistics only — motor current, voltage, back-EMF, door position
  and spectral summaries. No controller flag, no label, and no cross-segment
  information is used. (The `opening`/`closing` controller flags are explicitly
  *not* used, for either segmentation or features.)
- **No fold leakage.** Each CV fold fits a fresh `RandomForestClassifier` on
  its training folds only; the held-out fold is never seen during fitting.
- **No time leakage** in the chronological split: contiguous time blocks mean a
  test cycle is never bracketed in time by its own training neighbours.

## 5. Honest limitations

- Only 30 Abnormal segments exist, so the Abnormal F1 rests on a small sample;
  the 0.983 figure moves by ~0.03 per single misclassification.
- Training-set segmentation IoU is 1.000; on the held-out `Test.csv` stream,
  segment boundaries near very short inter-cycle gaps are the most likely place
  for timing error, which would down-weight those segments under the PS3
  IoU-weighted F1.
- Metrics are in-distribution (same door, same acquisition). Generalisation to
  a different door unit is not evidenced by this dataset.

## 6. Reproduce

```
python door_validate.py
```
Prints Sections 2–3 and writes `door_validation_results.json`.
